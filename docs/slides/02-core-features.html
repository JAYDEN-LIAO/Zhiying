COMPETITIVE ANALYSIS

Twelve Labs — 行业标杆，决策起点

🚀 Marengo 3.0 + Pegasus 1.5

Marengo 3.0 — 多模态视频嵌入模型（512 维专有空间），编码视觉帧 + 时序关系 + 语音 + 音频 + 文本五大模态，Any-to-Any 检索。36+ 语言，单次处理最长 4h 视频。

检索性能：composite video-retrieval 73%（Google Vertex 52%、Amazon Nova 55%），索引快 30 倍。已在 Amazon Bedrock 上架。

Pegasus 1.5 — 视频语言模型，三源（视觉+音频+语音）结构化解码，输出摘要+时间元数据+场景描述。支持小时级因果推理。

案例：UNICEF Korea 8TB 档案搜索时间 -95%；Getty Images 27 万素材接入语义搜索。

🔒 纯云路线的天花板

产品力第一梯队，但纯云架构是硬约束。 Twelve Labs 证明了视频语义搜索的产品可行性，同时也暴露了纯云路线在隐私合规场景的硬伤——这让它成为一个"用得好但用不上"的竞品。

数据流向：视频必须上传至美国服务器。金融/医疗/政府/安防场景直接出局。SOC 2 ≠ 数据不出境。

成本：$0.042/分索引 + $0.0292/分 Pegasus + $4/千次查询。日处理 100h 视频月成本破 $12,000。

锁定：Marengo + Pegasus 均为专有，不可替换。512 维高效的背面是换它就一切归零。

绝影同样全本地但走 Codebook 跨模态对齐，Mixpeek 走 pipeline 但依赖 Gemini 仍存数据出境问题——全本地+统一嵌入这个交叉点目前确实只有 Cerno 在尝试。

💡 它启发了我们什么

① Embedding — Marengo 让我们确信视频需要专用嵌入，不只是通用 CLIP。没条件自研，转而押注开源：Qwen3-VL-Emb-8B（MMEB-V2 77.8）是当时最优选，2048 维 vs 512 维的存储代价是主动接受的权衡。

② 检索架构 — Marengo 的 Any-to-Any 统一入口体验极佳。但我们担心单一向量空间同时做帧级定位和语义理解会两头不精，所以尝试 3 路并行 + scene 合并，让每条路径专注自己的粒度。是否更好需要 benchmark 验证。

③ 摘要方案 — Pegasus 最大的启发是"摘要独立于嵌入"的分层设计。我们无法复制其专有质量，所以用开源 LLM + Python 聚合器搭了四级阶梯，质量大概率不及 Pegasus，但覆盖了更多场景。
